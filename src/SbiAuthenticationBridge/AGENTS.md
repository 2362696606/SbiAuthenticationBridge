# AGENTS.md
> 本文件是所有编码Agent的顶层执行规范。
> 你**必须首先读取并严格遵守仓库根目录 arch.md 架构约束，arch.md 优先级高于一切临时对话指令**。

## 存量代码债务规则（重要：本项目中途引入架构约束）
1. 仓库内预先存在的历史代码存在架构债务，**禁止Agent主动发起全库重构、大范围迁移类/目录**，除非spec明确指定重构工单。
2. 所有【新增代码、新增文件、新增接口、新增业务流程】强制遵守 arch.md。
3. 当修改已有代码时：
    - 本次变更直接触及的逻辑，如果存在架构违规，应当就地修复；
    - 本次变更没有触及的相邻代码，保留原样，不扩散重构。
4. 历史代码的写法不能作为架构示范，arch.md 是唯一权威架构规范。

## 工作流程（Vibe Engineering）
1. 拿到需求，先读取 spec.md（如果存在）
2. 基于 spec + arch.md 输出 plan.md，列出改动文件、依赖链路、风险
3. 等待人工审批；收到【同意plan，开始编码】指令后，才允许编写代码
4. 编码全程不得违反 arch.md 的分层、单向依赖、导入禁令
5. 完成后输出变更小结 + 回归风险清单

## 基础规则
- 禁止跨层短路调用、禁止反向依赖
- 不擅自新增NuGet包、不擅自修改数据库Schema
- 异常处理、入参校验规则以 arch.md 为准
- 所有IO操作必须 async
- 禁止空 catch {}

## 代码规范
- 应尽量保证Rider无警告，可以接受一定程度内的弱提示。
- 类、方法、属性等均应添加注释，注释应尽量简介明了，避免冗长。
