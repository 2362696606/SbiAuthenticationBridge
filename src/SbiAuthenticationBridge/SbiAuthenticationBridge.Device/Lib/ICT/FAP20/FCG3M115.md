# FCG-3M115 采图迁移说明

本目录同时包含桌面与 Android 版 `ftmBridgeAPI`。认证采图在运行时选择协议：

- 配置了 FCG-3M115 Host 私钥：使用新协议，请求 336 字节、Host 私钥签名；响应
  124104 字节，包含 Module 证书、Module 整包签名与 RSA-OAEP 包装的 AES 密钥；
  解密后得到 120000 字节 300×400 GRAY8 原图。
- 未配置 Host 私钥：回退到旧版 `CAPTURE_AUTH` 紧凑二进制协议，由设备直接返回
  SBI 生物特征 JSON。

## 0. 确认固件是否支持 FCG-3M115

`ftm_load_certificate` 返回 0 只说明旧固件接受 LOAD_CERTIFICATE 命令，
**不能证明固件支持 FCG-3M115 采图**。确认方法是在下发 Host 证书后调用
`ftm_capture_auth`，观察响应格式：

| 固件 | `ftm_capture_auth` 响应 |
|---|---|
| FCG-3M115 | 124104 字节，以 `FCP1` 开头 |
| 旧固件 | JSON 文本，例如 `501 Invalid capture protocol`，或正常 SBI JSON |

已确认 `topeet_rk3576` 上当前的 FAP20 固件属于旧固件：336 字节探测请求返回

```json
{"biometrics":[{"specVersion":"0.9.5","data":"","hash":"","sessionKey":"","thumbprint":"","error":{"errorCode":"501","errorInfo":"Invalid capture protocol"}}]}
```

因此未配置 Host 私钥时应用会走旧版采集路径；配置 Host 私钥后才尝试 FCG-3M115。
设备级原始报文见第 7 节。

## 1. 运行时资产

| 资产 | 用途 | 放置位置 |
|---|---|---|
| `fcg3m115_root_ca.cert.der` | 验证响应中的 Module 证书 | 已内嵌到 `SbiAuthenticationBridge.Device`；可用 `FCG3M115_ROOT_CA` 覆盖 |
| `fcg3m115_android_host.cert.der` | 参考/对照用 Host 证书 | 已内嵌；实际上传的是 Host 密钥实现返回的证书 |
| Host P12/PEM | 签名请求、解包 AES 密钥 | 桌面：`FCG3M115_HOST_P12` + `FCG3M115_HOST_P12_PASSWORD`；Android：Keystore 别名 `fcg3m115_android_host` |
| SBI 应用公钥证书 | 加密 bioValue 会话密钥 | 桌面：`FCG3M115_APP_CERT`；Android：`FilesDir/fcg3m115_app.cert.der` 或 `Assets/fcg3m115_app.cert.der` |

**Host 私钥禁止放入 APK。** Android 必须先通过受控流程把 P12 导入 Keystore：

```text
别名：fcg3m115_android_host
用途：SIGN（SHA256withRSA） + DECRYPT（RSA/ECB/OAEPWithSHA-256AndMGF1Padding）
```

导入后 `Application.ConfigureFtmSdk()` 会自动从 Keystore 读取证书和私钥。

## 2. 桌面配置示例

```powershell
$env:FCG3M115_HOST_P12 = "D:\fcg3m115\private\fcg3m115_android_host.p12"
$env:FCG3M115_HOST_P12_PASSWORD = "<password>"
$env:FCG3M115_APP_CERT = "D:\fcg3m115\public\sbi_app.cert.der"
```

未配置时应用仍可启动、发现设备、查询 `/info` 和执行 DKL 密钥轮换；`/capture`
回退到旧版 `CAPTURE_AUTH` 协议，不会因缺少 Host 私钥直接返回 102。

## 3. SBI 采集响应

`Fap20AuthenticationDevice` 使用 Host 私钥签名 `data` JWT，并把解密后的原图作为
`bioValue`；`sessionKey` 使用 SBI 应用公钥证书按 RSA-OAEP-SHA256 包装。

已知限制：

1. **原图不是 ISO/IEC 19794-4 模板**。需要 ISO 校验（如 CTK 的 ISO 用例）时，
   必须在 `SbiCaptureResponseBuilder` 之前接入模板转换。
2. **JWT 由 Host 密钥签名**。新固件没有“用设备密钥签名任意数据”的命令，
   因此 `data`/`digitalId` 的 `x5c` 是 Host 证书，而不是 FTM 内部的 device key。
   如果 CTK 强制要求 device key 证书链，需要设备固件提供额外签名能力。
3. `qualityScore` 固定写 0：新固件不计算 NFIQ，接入质量评估后应改为真实分数。

## 4. 采图流程

```text
ConnectAsync
  → （Android）UsbManager 授权 + ClaimInterface + ftm_open_fd
EnsureDeviceCodeAsync
  → 一次 discover 取得 serialNo
EnsureHostCertificateAsync
  → ftm_load_certificate(Host DER)，每个连接一次
Fcg3M115Protocol.CreateRequest
  → 336 字节签名请求
CaptureSecureImageAsync
  → ftm_capture_auth，返回 124104 字节
Fcg3M115Protocol.VerifyAndDecrypt
  → Root 验 Module 证书、Module 验整包签名、OAEP 解包、AES-CTR 解密
SbiCaptureResponseBuilder.Create
  → AES-GCM 加密原图、包装会话密钥、签名 SBI JWT
```

设备重新上电、USB 复位或重新打开句柄后，`CloseDevice()` 会清除 Host 证书状态，
下一次采图会重新上传。

## 5. 与 SDK 验证脚本对照

`ftmBridgeAPI/verification/fcg3m115_host_verify.py` 是同一协议的参考实现。
可用其 `fcg3m115_request.bin` / `fcg3m115_response.bin` 离线核对本目录的 C# 实现。

## 6. SBI 请求/响应报文日志

Android 上每次 SBI Intent 调用都会把原始报文写入：

```text
/data/data/com.CompanyName.SbiAuthenticationBridge/files/sbi-messages/
  yyyyMMdd-HHmmss-fff-<action>-<id>-request.json
  yyyyMMdd-HHmmss-fff-<action>-<id>-response.json
  yyyyMMdd-HHmmss-fff-<action>-<id>-error.txt   （仅异常时）
```

保留最近 100 个文件。取回方式：

```bash
adb shell run-as com.CompanyName.SbiAuthenticationBridge ls files/sbi-messages
adb exec-out run-as com.CompanyName.SbiAuthenticationBridge \
  cat files/sbi-messages/<文件名> > local.json
```

报文包含加密后的生物特征数据，应按敏感数据处理。

## 7. 设备级原始报文日志

Android 上每次 `ftm_capture_auth`（正常采图或协议探测）还会把下发与返回的原始字节写入：

```text
/data/data/com.CompanyName.SbiAuthenticationBridge/files/fcg-messages/
  yyyyMMdd-HHmmss-fff-capture-auth-<id>-request.bin
  yyyyMMdd-HHmmss-fff-capture-auth-<id>-response.bin
  yyyyMMdd-HHmmss-fff-capture-auth-<id>-result.txt
  yyyyMMdd-HHmmss-fff-capture-probe-<id>-...（协议探测）
```

- `request.bin`：336 字节请求；
- `response.bin`：固定 124104 字节缓冲区，旧固件只使用前部，其余为零；
- `result.txt`：原生返回码、请求长度、响应缓冲区长度与最后一个非零字节位置。

`capture-probe` 使用零签名请求，仅用于判断响应是 `FCP1` 还是 JSON，不会得到有效图像。
取回方式与 SBI 报文相同，将路径改为 `files/fcg-messages` 即可。响应包含加密后的
生物特征数据，应按敏感数据处理。

## 8. Android USB 接口

FAP20（`0483:5725`）有两个接口：

- 接口 0：CDC ACM 控制接口（端点 `0x83`），内核 `cdc_acm` 会把它注册为 `ttyACM0`；
- 接口 1：CDC Data 接口，批量端点 `0x82`（IN）和 `0x01`（OUT），`ftmBridgeAPI` 实际使用这一组。

Android 上必须在 `ftm_open_fd` 之前对**两个接口**都执行
`UsbDeviceConnection.ClaimInterface(..., force: true)`。只声明接口 0 时，内核会记录
`usbfs: process ... did not claim interface 1 before use`，随后模组会断开并重新枚举；
应用仍持有旧 fd，后续命令返回原生错误码 `-4`（`LIBUSB_ERROR_NO_DEVICE`），
表现为采图失败或设备“未就绪”。

`FAP20.ThrowIfFailed` 遇到 `-4` 会关闭陈旧句柄，下一次 SBI 操作重新连接。
判断依据可查看：

```bash
adb shell dmesg | grep -E "usb 1-1.1|usbfs"
```
