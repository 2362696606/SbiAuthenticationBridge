# Plan:视图日志等级提升

> 需求：日志视图不再记录 Debug 日志，其他日志（文件、控制台）保持不变。

## 1. 现状

`LoggingBootstrapper.Configure` 里三路输出共用同一个全局最低级别 `Debug`：

| 输出 | 位置 | 当前级别 |
|---|---|---|
| 内存缓冲（LogView 数据源） | `.WriteTo.Sink(new SerilogLogEntrySink(store))` | Debug |
| 文件 | `.WriteTo.Async(File(...))` | Debug |
| 控制台 | `.WriteTo.Console()` | Debug |

LogView 的级别下拉里还有“全部（Trace）”“Debug”两项，同时
`LogViewModel.Matches` 默认按 `Trace` 过滤。

## 2. 方案

### 2.1 内存 Sink 单独提级

`SbiAuthenticationBridge/Logging/LoggingBootstrapper.cs`：

```csharp
.WriteTo.Sink(
    new SerilogLogEntrySink(store),
    restrictedToMinimumLevel: LogEventLevel.Information)
```

- 文件、控制台仍走全局 `MinimumLevel.Debug()`，**不受影响**；
- Debug/Verbose 事件在进入 Sink 前即被丢弃，不再渲染消息、不再占用内存缓冲。

### 2.2 视图级别选项同步收紧

`SbiAuthenticationBridge/ViewModels/LogViewModel.cs`：

- `LevelOptions` 移除“全部（Trace）”“Debug”两项，最低为 `Information`；
- 默认选中项由 `LevelOptions[0]` 自然变为 Information（无需额外赋值）。

理由：缓冲里已不存在 Debug 记录，保留这两项只会让用户选到一个永远没有增量的过滤档位。

## 3. 不做的事

- 不改 `MinimumLevel.Debug()` 全局级别；
- 不改文件/控制台 Sink；
- 不改 `SerilogLogEntrySink`、`LogEntryDto`、`ILogEntryStore`；
- 不改 LogView.axaml 布局。

## 4. 文件清单

| 文件 | 改动 |
|---|---|
| `SbiAuthenticationBridge/Logging/LoggingBootstrapper.cs` | 内存 Sink 增加 `restrictedToMinimumLevel: Information` |
| `SbiAuthenticationBridge/ViewModels/LogViewModel.cs` | 级别选项移除 Trace/Debug |

## 5. 风险

| 风险 | 等级 | 说明 |
|---|---|---|
| 排障时看不到 Debug | 低 | Debug 仍完整写入文件 `Logs/sbi-.log` 与控制台，需要时可查文件 |
| 选项数量变化 | 低 | 仅 UI 下拉项减少，无行为逻辑依赖索引 |

## 6. 验证

1. 构建桌面端，0 警告 0 错误；
2. 运行后触发一次 Debug 日志路径（如设备轮询），确认：
   - 日志视图无 Debug 行；
   - `Logs/sbi-*.log` 中仍能看到 Debug 行；
3. 级别下拉最低项为 Information。
