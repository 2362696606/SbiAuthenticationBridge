# Plan:修复质量分解析导致的采集 102

> 依据：`Logs/sbi-20261027.log` 中 CTK SBI1018 的原始收发记录。

## 1. 现象

设备连续返回 3 帧成功采集：

```text
09:40:59.441 ftm_capture_auth 响应 rc=0x0 TEXT=... "errorCode":"0"
09:41:01.153 ftm_capture_auth 响应 rc=0x0 TEXT=... "errorCode":"0"
09:41:02.853 ftm_capture_auth 响应 rc=0x0 TEXT=... "errorCode":"0"
09:41:06.614 CAPTURE 响应体：{"errorCode":"102","errorInfo":"Technical error during extraction"}
```

解析成功帧的 JWT payload：

```text
requestedScore: "60"   (字符串)
qualityScore:  "100"  (字符串)
```

## 2. 根因

`FAP20Proxy.ExtractQualityScore` 只把 JSON **数字**当作有效质量分：

```csharp
score.ValueKind == JsonValueKind.Number
```

固件返回的是字符串 `"100"`，因此返回 0：

1. `0 < requestedScore(60)` → 成功帧被判为质量不达标
2. 继续轮询，直到 SBI 超时
3. `CaptureNormalAsync` 返回 `null` → 映射为 102

SBI1057 之前能过，是因为 `requestedScore=100` 路径只要求“采到过一帧”，
质量分 0 也会被当作 best 返回。

## 3. 修复

`SbiAuthenticationBridge.Device/FAP20Proxy.cs`：

- 新增 `ParseScore(JsonElement)`：
  - `Number` → `GetDouble()`
  - `String` → `double.TryParse(..., NumberStyles.Float, CultureInfo.InvariantCulture, ...)`
  - 其他 → 0
- `ExtractQualityScore` 改为调用 `ParseScore`。
- 不改其他逻辑。

## 4. 文件清单

| 文件 | 改动 |
|---|---|
| `SbiAuthenticationBridge.Device/FAP20Proxy.cs` | 质量分解析同时支持 JSON 数字与字符串 |

## 5. 风险

| 风险 | 等级 | 说明 |
|---|---|---|
| 字符串格式异常 | 低 | `TryParse` 失败仍返回 0，行为与现在一致 |
| 其他调用方 | 低 | `ExtractQualityScore` 仅用于质量门限与 1057 选帧 |

## 6. 验证方式

1. 构建 Desktop。
2. 重启应用，发起认证采集：
   - 成功帧不再被丢弃；
   - HTTP 响应为 `errorCode=0`，包含 `data/hash/sessionKey/thumbprint/dataDecoded`。
3. 重跑 CTK，观察 1018-1021 以及 1069/1082/1090/1107。
