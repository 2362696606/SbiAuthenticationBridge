# Plan:添加文件日志

> 对应 spec：`specs/20261026-添加文件日志.spec.md`
> 依据：arch.md、现有 `LoggingBootstrapper`、已引入的 Serilog 附加包。

## 0. 现状

- `Directory.Packages.props` 已声明并在应用项目引用：
  - `Serilog.Sinks.Async` 2.1.0
  - `Serilog.Sinks.File` 7.0.0
- `LoggingBootstrapper` 目前只接内存 Sink 与 Console，文件日志尚未启用。
- 因此本需求不需要新增 NuGet，只需使用已引用的 Serilog 附加包。

## 1. 方案

### 1.1 文件 Sink

在 `SbiAuthenticationBridge/Logging/LoggingBootstrapper.cs` 中增加：

```csharp
.WriteTo.Async(sink => sink.File(
    path: Path.Combine(AppContext.BaseDirectory, "Logs", "sbi-.log"),
    rollingInterval: RollingInterval.Day,
    retainedFileCountLimit: 7,
    fileSizeLimitBytes: 32 * 1024 * 1024,
    rollOnFileSizeLimit: true,
    flushToDiskInterval: TimeSpan.FromSeconds(1)))
```

- 路径：`bin/.../Logs/sbi-yyyyMMdd.log`，按天滚动；
- 单文件上限 32MB，超出滚动；最多保留 7 个文件；
- `flushToDiskInterval` 1 秒，减少异常退出时的丢失；
- 最低级别沿用 `Debug`，请求/响应体同时落盘。

### 1.2 异步 Sink

- 文件 Sink 外层使用 `WriteTo.Async(...)`；
- 默认容量 10000，队列满时丢弃最旧日志（`blockWhenFull: false`），不阻塞业务线程；
- 内存 Sink 与 Console 保持同步，不影响 LogView 实时性。

### 1.3 启动日志

- 启动时输出日志文件完整路径，便于定位。

### 1.4 不修改

- 不新增/升级 NuGet；
- 不改 Host/Device/HTTP 层；
- 不改现有日志内容与级别。

## 4. 风险

| 风险 | 等级 | 说明 |
|---|---|---|
| 请求/响应体落盘包含生物特征 JWT、sessionKey | 中 | 仅保存在本机 `Logs` 目录；CTK 排查结束后可删除 |
| 应用异常退出时最后 1 秒日志可能丢失 | 低 | `flushToDiskInterval` 1 秒；正常退出 `CloseAndFlush` 会排空 |
| 日志文件增长 | 低 | 按天滚动 + 32MB 上限 + 保留 7 个 |
| 异步队列满时丢弃旧日志 | 低 | 只在极端日志量下发生，内存 LogView 仍保留最近 2000 条 |

## 5. 验证方式

1. 构建 Desktop。
2. 启动应用，确认生成 `bin/Debug/net10.0/Logs/sbi-yyyyMMdd.log`。
3. 调用 `/device`、`/capture`，确认请求体、响应体、域证书加载日志写入文件。
4. 关闭应用，确认文件完整、无截断。
