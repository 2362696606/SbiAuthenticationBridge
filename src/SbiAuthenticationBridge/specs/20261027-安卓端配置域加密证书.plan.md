# Plan:安卓端配置域加密证书

> 现象：Android 端发起认证采集时提示“未配置域加密证书”。
> 依据：`FileCertificateProvider`、`SbiAuthenticationServiceHandle.PrepareDeviceAsync`、Android 配置加载链路。

## 1. 根因

认证采集前会读取 `CertificateProvider:domainEncryptionCertificatePath` 指定证书，
用于加密 sessionKey。Android 的 AppSetting 里是 Windows 绝对路径
（`E:/code/.../device-provider/key.cer`），设备上不存在 → 证书为 null →
采集返回 `108 Domain public key missing`。

## 2. 方案：配置改为 Android 可访问路径

不打包证书资产、不改代码，只把 Android 侧配置改成设备上的真实路径，
证书文件由部署时手工放入应用私有目录。

### 2.1 路径约定

应用私有目录（`FilesDir`）：

```text
/data/data/com.CompanyName.SbiAuthenticationBridge/files
```

证书统一放在其下的 `device-provider/`：

| 配置键 | Android 路径 |
|---|---|
| `CertificateProvider:providerCertificatePath` | `/data/data/com.CompanyName.SbiAuthenticationBridge/files/device-provider/ict_device_provider.cert.der` |
| `CertificateProvider:providerPrivateKeyPath` | `/data/data/com.CompanyName.SbiAuthenticationBridge/files/device-provider/ict_device_provider.key.pem` |
| `CertificateProvider:domainEncryptionCertificatePath` | `/data/data/com.CompanyName.SbiAuthenticationBridge/files/device-provider/key.cer` |
| `Dkl1Issuer:issuedCertificatePath` | `/data/data/com.CompanyName.SbiAuthenticationBridge/files/device-provider/dkl1_device.cer` |

### 2.2 修改文件

- `SbiAuthenticationBridge.Android/Config/AppSetting.example.yaml`：写入上面的 Android 路径；
- `SbiAuthenticationBridge.Android/Config/AppSetting.yaml`（本地、不入库）：同样修改。

### 2.3 不做的事

- 不把证书打包进 APK（域证书虽为公钥，但按部署时下发更灵活）；
- 不改 `FileCertificateProvider`、不改桌面配置；
- 不引入路径占位符/内存配置覆盖。

## 3. 需要上传的文件

直接上传到设备上的应用私有目录（目录不存在时先创建）：

```text
/data/data/com.CompanyName.SbiAuthenticationBridge/files/device-provider/
```

| 文件 | 是否必需 | 说明 |
|---|---|---|
| `key.cer` | **必需** | MOSIP 域加密证书（PEM），认证采集加密 sessionKey |
| `ict_device_provider.cert.der` | 可选 | DKL1 签发用 |
| `ict_device_provider.key.pem` | 可选 | DKL1 签发用，敏感材料 |
| `dkl1_device.cer` | 否 | 由应用签发后写入，不需要预置 |

## 4. 文件清单

| 文件 | 改动 |
|---|---|
| `SbiAuthenticationBridge.Android/Config/AppSetting.example.yaml` | 证书路径改为 Android 路径 |
| `SbiAuthenticationBridge.Android/Config/AppSetting.yaml`（本地） | 同步修改 |

## 5. 风险

| 风险 | 等级 | 说明 |
|---|---|---|
| FilesDir 路径硬编码 | 低 | 路径与 ApplicationId 绑定；改包名需同步改配置 |
| 文件缺失 | 低 | 未部署时行为与现在一致（108），日志会提示路径 |
| 私有目录访问权限 | 低 | 需通过设备文件管理/Android Studio Device Explorer 等直接访问应用私有目录的方式上传 |

## 6. 验证方式

1. 重新构建并安装 APK（配置会随资产打包）；
2. 按第 3 节复制 `key.cer`；
3. 重启应用，CTK 发起认证采集：不再返回 `108`，响应包含 `sessionKey` 与 `thumbprint`；
4. 若仍失败，检查日志中的证书路径与文件是否存在。
