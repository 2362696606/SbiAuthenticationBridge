# Plan:完善日志（设备操作）

> 对应 spec：`specs/20261026-完善日志.spec.md`
> 仅改 `DeviceOperateViewModel`，通过现有 MEL → Serilog 管线记录；不新增 NuGet，不改 Core/Device/视图。

## 0. 前置决策

| 项 | 决策 / 说明 |
|---|---|
| 日志入口 | 设备操作由 `DeviceOperateViewModel` 发起，在该层注入 `ILogger<DeviceOperateViewModel>`，复用 `LoggingBootstrapper` 已配置的 Serilog 管线（Console + 内存 LogView） |
| 覆盖范围 | 连接、断开、修改状态、轮换密钥；额外为刷新状态失败补一条 `Warning`（避免静默失败） |
| 级别 | 操作开始 `Debug`；状态变更成功 `Information`；失败 `Error`（含异常）；刷新失败 `Warning` |
| 结构化字段 | `DeviceId`（内部标识）、`DeviceType`（实现类名）、`Status`（枚举）、`Subject`（DKL1 叶证书主题） |
| 脱敏 | 不记录私钥、证书 DER、生物特征数据；异常对象仅由日志框架记录堆栈，不额外输出敏感内容 |
| 连接失败判定 | 仅当 `device.IsConnected == false` 时记“连接失败”；已连接但读取状态失败记 `Warning`，避免误报 |

## 1. 方案总览

```
DeviceOperateView
  └─ DeviceOperateViewModel（注入 ILogger<DeviceOperateViewModel>）
       ├─ ConnectAsync    → Debug 开始 / Information 成功 / Error 失败
       ├─ DisconnectAsync → Debug 开始 / Information 成功 / Error 失败
       ├─ SetStatusAsync  → Debug 开始 / Information 成功（含状态） / Error 失败
       ├─ RotateKeyAsync  → Debug 开始 / Information 完成（含 Subject） / Error 失败
       └─ RefreshStateAsync → Warning 失败（保留现有静默成功）
              │
              ▼
       MEL → Serilog → Console / 内存 LogView
```

## 3. 关键实现细节

### 3.1 构造函数

```csharp
public DeviceOperateViewModel(
    IDeviceSelectionService selectionService,
    ICertificateProvider certificateProvider,
    IOptions<Dkl1IssuerOptions> dkl1Options,
    IEventAggregator eventAggregator,
    ILogger<DeviceOperateViewModel> logger)
```

- `ArgumentNullException.ThrowIfNull(logger)`；
- DryIoc 从组合根解析 `ILogger<DeviceOperateViewModel>`，无需额外注册。

### 3.2 连接

- 开始：`LogDebug("开始连接设备：{DeviceId}，类型={DeviceType}", selectedDeviceId, device.GetType().Name)`
- `await device.ConnectAsync()` 成功后：`LogInformation("设备已连接：{DeviceId}，类型={DeviceType}", ...)`
- 失败：
  - `device.IsConnected == false` → `LogError(exception, "连接设备失败：{DeviceId}", ...)`
  - 已连接但后续 `LoadDeviceStateAsync` 失败 → `LogWarning(exception, "设备已连接，但读取状态失败：{DeviceId}", ...)`
- 不记录设备返回的敏感数据。

### 3.3 断开

- 开始：`LogDebug("开始断开设备：{DeviceId}", ...)`
- 成功：`LogInformation("设备已断开：{DeviceId}", ...)`
- 失败：`LogError(exception, "断开设备失败：{DeviceId}", ...)`

### 3.4 修改状态

- 开始：`LogDebug("开始设置设备状态：{DeviceId} -> {Status}", selectedDeviceId, statusOption.Value)`
- 成功：`LogInformation("设备状态已设置：{DeviceId} -> {Status}", ...)`
- 失败：`LogError(exception, "设置设备状态失败：{DeviceId} -> {Status}", ...)`

### 3.5 轮换密钥

- 开始：`LogDebug("开始轮换设备密钥：{DeviceId}", ...)`
- 成功：`LogInformation("设备密钥轮换完成：{DeviceId}，Subject={Subject}", selectedDeviceId, KeySubjectDescription)`
- 失败：`LogError(exception, "设备密钥轮换失败：{DeviceId}", ...)`
- 不记录生成的证书内容、公钥或私钥。

### 3.6 刷新状态（补充）

- 现有成功路径保持静默，避免高频日志；
- `catch` 中补 `LogWarning(exception, "刷新设备状态失败：{DeviceId}", deviceId)`，与现有 `ErrorMessage` 并存。

## 4. 依赖链路与架构自查

- `ILogger<T>` 来自 `Microsoft.Extensions.Logging`（项目已有依赖），实现由组合根提供，符合 arch 分层。
- 不引用 Device/Host 实现；不新增 NuGet；不改 Core 接口。
- 无空 catch；所有异常路径均有 `LogError`/`LogWarning` 并保留原有 `ErrorMessage` 行为。
- 日志字段均为标识类信息，不含密钥/证书/生物特征。

## 5. 风险与回滚

| 风险 | 等级 | 说明 / 缓解 |
|---|---|---|
| 日志噪声 | 低 | 开始用 `Debug`，成功用 `Information`；刷新成功不记录 |
| 操作失败日志重复 | 低 | 每个命令仅在自身 `catch` 记录一次；不叠加事件/列表层日志 |
| 连接成功但状态读取失败被误记为连接失败 | 低 | 按 `device.IsConnected` 区分 Error/Warning |
| 敏感信息泄露 | 低 | 只记录 ID、类型、状态、Subject；不记录密钥/证书 DER |
| 硬件层缺少日志 | 低 | 本次覆盖用户操作边界；FAP20 底层日志需另立工单并引入 Logging.Abstractions |

   - 校验日志正文不含私钥、证书 DER。
3. 启动 Desktop，操作设备后在 LogView 中确认日志按级别显示。
4. 逐文件对照 arch.md 依赖红线。
