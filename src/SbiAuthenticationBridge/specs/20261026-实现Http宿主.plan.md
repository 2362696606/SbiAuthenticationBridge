# Plan:实现 HTTP 宿主

> 对应 spec：`specs/20261026-实现Http宿主.spec.md`
> 遵循 `arch.md`：不新增 NuGet；不跨层引用；基础设施实现类 internal；仅组合根做 DI 装配。
> 本期只做「宿主生命周期 + 路由映射」，**不实现任何 SBI 业务**（`ISbi*ServiceHandle` 的具体实现仍由 Host 项目后续工单提供）。

## 1. 方案总览

```
SbiAuthenticationBridge.Desktop (平台入口 + 组合根扩展点)
  └─ PlatformServiceRegistrations: services.AddSbiHttpServices()
        │
        ▼
SbiAuthenticationBridge.Host.Http  (Infrastructure / HTTP 网关)
  ├─ SbiHttpServiceBase (internal)
  │    ├─ 生命周期：StartAsync/StopAsync + SemaphoreSlim 串行化
  │    ├─ 每个实例一个 WebApplication(Kestrel)，IP 强制 IPAddress.Loopback
  │    └─ 共用：JSON、异常边界、CORS、日志
  ├─ SbiAuthenticationHttpService  → 端口 A
  │    └─ /device、/info、/capture   → ISbiAuthenticationServiceHandle
  └─ SbiRegistrationHttpService    → 端口 B
       └─ /device、/info、/rcapture、/stream → ISbiRegistrationServiceHandle
        │
        ▼
SbiAuthenticationBridge.Core  (仅抽象)
  ├─ ISbiService（StartAsync / StopAsync）
  │    ├─ ISbiAuthenticationService      （宿主无关，上层可依赖）
  │    ├─ ISbiRegistrationService        （宿主无关，上层可依赖）
  │    └─ ISbiHttpService（Port）
  ├─ ISbiAuthenticationHttpService : ISbiAuthenticationService, ISbiHttpService
  ├─ ISbiRegistrationHttpService   : ISbiRegistrationService,   ISbiHttpService
  ├─ ISbiHostContext（按 DevicePurpose 读写 callbackId）
  └─ ISbiAuthenticationServiceHandle / ISbiRegistrationServiceHandle
```

- 两个服务实现不共享路由表：Authentication 类只映射认证端点，Registration 类只映射注册端点；`/device`、`/info` 虽同名，但各自解析本用途的句柄。
- 本期 Host 项目尚无 `ISbi*ServiceHandle` 实现，两个宿主仍可启动；请求命中路由时若实现未注册，返回 HTTP 500 + `ErrorResponse`，不影响宿主启动。
- 不注册任何假实现 / 桩实现。

## 4. 关键实现细节

### 4.1 生命周期（每个服务实例独立）

- `Port`：
  - 默认 `0`；赋值范围 0–65535，越界抛 `ArgumentOutOfRangeException`；
  - `IsRunning == true` 时赋值抛 `InvalidOperationException`；
  - `StartAsync` 成功后写回实际绑定端口（端口为 0 时由 Kestrel/OS 分配）。
- `StartAsync()`：
  1. `SemaphoreSlim.WaitAsync` 串行化；
  2. 已启动 → 抛 `InvalidOperationException("服务已启动")`；
  3. 构建 `WebApplication` 并启动；Kestrel 只绑定 `IPAddress.Loopback`；
  4. 从 `IServerAddressesFeature` 读取实际端口，写回 `Port`；
  5. `ISbiHostContext.SetCallbackId(Purpose, $"http://127.0.0.1:{Port}")`；
  6. 启动失败时释放已构建的 `WebApplication` 后抛出（附加上层可读的绑定失败信息）。
- `StopAsync()`：未启动时幂等空操作；启动中则 `StopAsync` + `DisposeAsync`；`Port` 保留最后一次实际端口，重启时复用（如需新端口由上层重新赋值）。
- 不自动启动、不监听应用退出事件；启动方仍为上层（后续 UI 工单）。
- 两个服务可以同时运行在不同端口；若上层把两个 `Port` 设为同一值，后启动者绑定失败并抛出，互不影响已运行实例。

### 4.2 Kestrel 与 DI 桥接

- 每个实例使用 `WebApplication.CreateSlimBuilder(new WebApplicationOptions { Args = [], ContentRootPath = AppContext.BaseDirectory })`，仅启用 Kestrel + Routing + JSON，不引入 MVC/Swagger。
- `builder.WebHost.ConfigureKestrel(o => o.Listen(IPAddress.Loopback, Port))`。
- 日志：把组合根的 `ILoggerFactory`（Serilog 桥接）注册进 WebApplication，ASP.NET Core 与路由日志统一进入现有 LogView；不新增日志依赖。
- 业务抽象桥接：基类注入组合根的 `IServiceProvider`；派生类在构建 WebApplication 时只注册**本用途**的委托工厂：
  - Authentication：`builder.Services.AddSingleton(_ => appServices.GetRequiredService<ISbiAuthenticationServiceHandle>())`
  - Registration：`builder.Services.AddSingleton(_ => appServices.GetRequiredService<ISbiRegistrationServiceHandle>())`
  
  这样不在 HTTP 容器里复制有状态单例；未注册时只在请求命中该路由时失败，不影响启动。
- DI 注册（`AddSbiHttpServices`）：
  ```csharp
  services.AddSingleton<ISbiAuthenticationHttpService, SbiAuthenticationHttpService>();
  services.AddSingleton<ISbiAuthenticationService>(sp => sp.GetRequiredService<ISbiAuthenticationHttpService>());
  services.AddSingleton<ISbiRegistrationHttpService, SbiRegistrationHttpService>();
  services.AddSingleton<ISbiRegistrationService>(sp => sp.GetRequiredService<ISbiRegistrationHttpService>());
  ```
  用途接口解析到同一个 HTTP 实现实例；上层可只依赖用途接口启停，需要读写端口时再依赖 HTTP 接口。不直接注册 `ISbiService`，避免两个用途注入歧义。
- 组合根约定（写在代码注释中）：Host 实现须把同一实例按其用途接口注册，Authentication / Registration 不得互相替代。

### 4.3 路由表（两个服务各自映射，互不混合）

**Authentication 服务**

| 路径 | HTTP 方法 | Core 调用 | 成功响应 |
|---|---|---|---|
| `/device` | `MOSIPDISC`、`POST` | `ISbiAuthenticationServiceHandle.DiscoverAsync` | `DiscoveryResponse[]` |
| `/info` | `MOSIPDINFO`、`POST` | `ISbiAuthenticationServiceHandle.GetDeviceInfoAsync` | `DeviceInfoResponse[]` |
| `/capture` | `CAPTURE`、`POST` | `ISbiAuthenticationServiceHandle.CaptureAsync` | `CaptureResponse` |

**Registration 服务**

| 路径 | HTTP 方法 | Core 调用 | 成功响应 |
|---|---|---|---|
| `/device` | `MOSIPDISC`、`POST` | `ISbiRegistrationServiceHandle.DiscoverAsync` | `DiscoveryResponse[]` |
| `/info` | `MOSIPDINFO`、`POST` | `ISbiRegistrationServiceHandle.GetDeviceInfoAsync` | `DeviceInfoResponse[]` |
| `/rcapture` | `RCAPTURE`、`POST` | `ISbiRegistrationServiceHandle.CaptureAsync` | `CaptureResponse` |
| `/stream` | `STREAM`、`POST` | `ISbiRegistrationServiceHandle.StreamAsync` | M-JPEG 流；失败时 `ErrorResponse` |

- 用 `MapMethods` 声明自定义 verb（Kestrel 接受非标准 HTTP method token）。
- `POST` 是给 CTK/标准客户端用的兼容入口，语义与对应自定义 verb 一致。
- 路由隔离：Authentication 端口上 `/rcapture`、`/stream` 为 404；Registration 端口上 `/capture` 为 404。
- 请求体：`/device`、`/stream` 允许空 body（按空对象处理）；`/capture`、`/rcapture` 空 body 或非法 JSON → `400 + ErrorResponse`。

### 4.4 协议序列化

- 请求：`JsonSerializerOptions(JsonSerializerDefaults.Web)`，兼容大小写；空 body 不抛 400（除采集类）。
- 响应：`application/json; charset=utf-8`；`DefaultIgnoreCondition = WhenWritingNull`，避免输出大量 `"xxx": null`（`BiometricInfo.SessionKey/Thumbprint` 已有特性，保持）。
- SBI 业务错误统一 HTTP 200 + `ErrorResponse`（与参考项目一致）；只有传输层/服务器内部错误才用 4xx/5xx，响应体仍为 `ErrorResponse`。
- `/stream` 成功：`Content-Type: multipart/x-mixed-replace; boundary=--sbi-frame`，`CopyToAsync` 原样转发并负责释放设备流。边界常量集中在 `SbiHttpProtocol`。

### 4.5 错误映射

- `SbiException`：取 `Error`，HTTP 200 + `ErrorResponse`。
- `OperationCanceledException` 且 `RequestAborted` 已触发：不再写响应。
- 其他异常（含 Core 句柄未注册）：HTTP 500 + `ErrorResponse { Error = SbiErrorHelper.Custom(500, "Internal server error") }`；完整异常写入日志，不回传堆栈。
- 禁止空 catch；所有异常路径均记录日志。

### 4.6 CORS 与本地网络

- 每个服务各自 `AddCors`：`AllowAnyOrigin` + 显式方法列表（`MOSIPDISC/MOSIPDINFO/CAPTURE/RCAPTURE/STREAM/POST/OPTIONS`）+ `Content-Type, Authorization`。
- 预检时若带 `Access-Control-Request-Private-Network: true`，响应补 `Access-Control-Allow-Private-Network: true`（Chrome 本地网络访问要求）。作为中间件放在 CORS 之前。
- 仅监听回环地址，不对外网暴露；CORS 放开是为了浏览器端 CTK 访问本机服务（与参考项目一致），风险见第 6 节。

### 4.7 回调标识

- 两个服务启动成功后分别写 `ISbiHostContext.SetCallbackId(Purpose, "http://127.0.0.1:{各自端口}")`，互不覆盖。
- 格式无尾斜杠，沿用 `App.axaml.cs` 现有初始化值风格。
- `ISbiServiceHandle.CallbackId` 由 Host 实现每次请求按自身用途读取，本期不缓存、不代持。

## 5. 依赖链路与架构自查

- `Core`：仅新增/调整接口，无任何实现/HTTP/Avalonia 依赖。
- `Host.Http → Core`：合法；未引用 `Host`（本期不需要）、未引用 UI/Prism/DryIoc。
- `Desktop → Host.Http`：仅 `DesktopAppBuilder` 注册宿主，符合 arch 第 79 行与调整后的第 84 行；`Desktop` 不写业务。
- `SbiAuthenticationBridge`（共享应用）：只新增平台注册扩展点，**不引用 Host.Http**，避免 ASP.NET Core 共享框架传递到 Android/iOS/Browser。
- `ViewModel/Handler`：本期零改动，不存在直接引用基础设施实现的情况；后续只依赖 `ISbiAuthenticationService` / `ISbiRegistrationService` 即可启停，不感知 HTTP；端口配置由平台/HTTP 层负责。
- 无反向依赖、无跨层短路、无 ServiceLocator：路由依赖走 DI 注册的委托工厂；两个服务实现类 internal。
- 无空 catch；所有 IO 与请求处理 async。

## 6. 风险与回滚

| 风险 | 等级 | 说明 / 缓解 |
|---|---|---|
| Core 契约变更（新增接口 + `ISbiHostContext` 改形状） | 高 | arch 要求核心契约变更人工确认；当前无实现依赖旧 `CallbackId`，改造成本可控；回滚 = 还原 Core 两个文件并删除新增接口 |
| Desktop 引用 Host.Http 的架构边界 | 低 | arch 第 79 行允许平台宿主注册，第 84 行已同步移除对 Host.Http 的禁令；Desktop 只在 `DesktopAppBuilder` 做注册 |
| `Microsoft.AspNetCore.App` 共享框架依赖 | 中 | 桌面端发布/自包含部署必须带 ASP.NET Core 运行时；不新增 NuGet，回滚仅需移除 FrameworkReference |
| DryIoc 对 `IServiceProvider` 注入的支持 | 中 | 落地时先跑通宿主解析；若不可用，改为在组合根注册时传入解析委托（不改 Core） |
| 自定义 HTTP verb 兼容性 | 中 | Kestrel + `MapMethods` 支持非标准 token；验证阶段用 `curl -X MOSIPDISC` 实测 |
| `/stream` 边界常量与未来设备流实现不一致 | 中 | 常量集中在 `SbiHttpProtocol`，Host/Device 实现 M-JPEG 分帧时按该常量输出；实施时在注释中固化约定 |
| 两个服务同时运行占用两个端口 | 低 | 各自独立 `WebApplication`；端口冲突由后启动者报错，不影响前者 |
| CORS 放开任意来源 | 中 | 服务仅监听 127.0.0.1；若安全评审要求，可改为来源白名单（后续配置项） |
| Host 实现未注册时接口全部 500 | 低 | 本期预期行为；宿主启停、路由、错误报文仍可验证，Host 工单接入后即恢复 |
| `Port` 运行中被篡改 | 低 | setter 在运行中抛 `InvalidOperationException`；启动/停止由 `SemaphoreSlim` 串行化 |

## 7. 验收对照

| spec 要求 | 实现点 |
|---|---|
| 包含启动与停止 | `ISbiService.StartAsync/StopAsync`，两个 HTTP 服务各自实现 |
| 允许上层传递端口号 | `ISbiHttpService.Port` 先赋值再启动；0 = 系统分配，启动后回写实际端口 |
| IP 固定 127.0.0.1 | 两个 Kestrel 均绑定 `IPAddress.Loopback`，无配置项 |
| Host.Http 只提供服务与路由，不提供具体实现 | 两个服务只调用 Core 的 `ISbi*ServiceHandle`；无任何业务实现、无桩实现 |
| 主机项目提供具体实现 | 通过 `IServiceProvider` 委托工厂从组合根解析 Host 注册的实例，按用途分离 |
| Authentication / Registration 分别路由 | 两个独立监听、两个独立路由类；认证端口无 `/rcapture`、`/stream`，注册端口无 `/capture` |
| 上层可复用宿主无关抽象 | `ISbiAuthenticationService` / `ISbiRegistrationService` 从 `ISbiService` 派生；HTTP 接口再从用途接口派生。未来 Intent 等宿主可复用同一对用途接口 |
| 本次不做具体接口与功能实现 | 不实现 `ISbi*ServiceHandle`、不做 UI、不做设备交互 |

## 8. 验证方式

1. `dotnet build SbiAuthenticationBridge.sln`（或 Desktop 项目）确认无新增错误/警告。
2. 在系统临时目录建一个一次性控制台程序引用 `SbiAuthenticationBridge.Host.Http`（不提交仓库）：

   - `OPTIONS` 预检验证 CORS 头；
   - `StopAsync()` 后确认端口释放；两个服务分别启停互不影响。
