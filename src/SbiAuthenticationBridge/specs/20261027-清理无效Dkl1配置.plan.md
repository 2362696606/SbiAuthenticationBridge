# Plan:清理无效 Dkl1Issuer 配置

> 依据：`Dkl1IssuerOptions` 只绑定 `IssuedCertificatePath`，
> 叶证书 Subject 由设备 digitalId 与 Device Provider 证书动态生成，
> `serialNo/make/model/deviceProvider` 四个键在代码中无任何读取点。

## 1. 改动内容

从配置文件中删除以下 4 个键（保留 `Dkl1Issuer.issuedCertificatePath`）：

```yaml
Dkl1Issuer:
  serialNo: "123456789012"
  make: "CCM"
  model: "CCM4201S"
  deviceProvider: "FTM-Test"
  issuedCertificatePath: ...   # 保留
```

## 2. 文件清单

| 文件 | 改动 |
|---|---|
| `SbiAuthenticationBridge.Android/Config/AppSetting.yaml`（本地，不入库） | 删除 4 个键 |
| `SbiAuthenticationBridge.Android/Config/AppSetting.example.yaml` | 删除 4 个键及对应注释 |
| `SbiAuthenticationBridge.Desktop/Config/AppSetting.example.yaml` | 删除 4 个键及对应注释 |

桌面实际配置 `SbiAuthenticationBridge.Desktop/Config/AppSetting.yaml` 已经没有这些键，无需改动。

## 3. 不做的事

- 不改 `Dkl1IssuerOptions`、不改 DKL1 签发逻辑；
- 不改 `Device:` 段（安卓 USB 枚举必需）；
- 不改 `CertificateProvider` 段。

## 4. 风险

| 风险 | 等级 | 说明 |
|---|---|---|
| 键被隐式读取 | 极低 | 已全仓检索 `Dkl1Issuer` / `SerialNo` 等，仅 App.axaml.cs 绑定 section 到 Options |
| 设备端旧配置不更新 | 低 | 设备上的 `files/AppSetting.yaml` 不会自动覆盖，需手工删除或覆盖；即便保留旧键也无影响 |

## 5. 验证

1. 重新打包 Android，确认 APK 内 `assets/Config/AppSetting.yaml` 已无这 4 个键；
2. 桌面端启动一次，DKL1 签发仍能正常写 `issuedCertificatePath`。
