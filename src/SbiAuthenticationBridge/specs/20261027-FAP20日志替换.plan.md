# Plan:FAP20 日志替换

> 对应 spec：`specs/20261027-FAP20日志替换.spec.md`
> 依据：arch.md、`FAP20` 已注入 `ILogger<FAP20>`。

## 1. 现状

`SbiAuthenticationBridge.Device/FAP20.cs` 仍有 5 处 `Debug.WriteLine`：

| 位置 | 场景 |
|---|---|
| 断开时释放句柄失败 | 异常 |
| 证书加载完成 | 长度 + SHA-256 |
| 0x75 但句柄为空 | 跳过软复位 |
| 0x75 软复位结果 | 成功/失败码 |
| 0x75 软复位异常 | 异常 |

这些信息只进入调试器输出，不进入内存日志与文件日志。

## 2. 方案

### 2.1 替换为 `ILogger`

统一使用已有的 `_logger`（可空），通过 `_logger?.LogXxx(...)` 调用：

| 场景 | 替换为 | 级别 |
|---|---|---|
| 释放句柄失败 | `LogWarning(exception, ...)` | Warning |
| 证书加载完成 | `LogDebug(...)` | Debug |
| 0x75 句柄为空 | `LogDebug(...)` | Debug |
| 0x75 软复位成功 | `LogDebug(...)` | Debug |
| 0x75 软复位失败 | `LogDebug(..., resetResult)` | Debug |
| 0x75 软复位异常 | `LogWarning(exception, ...)` | Warning |

- 使用结构化参数（命令名、长度、指纹、返回码），不做字符串插值；
- 不重复 Host 层已有的“域证书已加载”Info 日志，这里保持 Debug；
- 异常路径使用 Warning，保证默认日志级别下可见。

### 2.2 清理 using

替换完成后 `System.Diagnostics` 不再被使用，移除该 using。

### 2.3 不修改

- 不改 JWT 解析、命令编码、超时、复位逻辑；
- 不改 `FAP20Proxy` 中的 `Debug.WriteLine`（spec 范围仅 FAP20）；
- 不新增 NuGet。

## 3. 文件清单

| 文件 | 改动 |
|---|---|
| `SbiAuthenticationBridge.Device/FAP20.cs` | 5 处 `Debug.WriteLine` 改为 `ILogger`；移除 `System.Diagnostics` |

## 4. 架构与依赖自查

- 仅 Device 层内部日志替换；
- `Microsoft.Extensions.Logging.Abstractions` 已在 Device 项目引用；
- 无跨层依赖与接口变化。

## 5. 风险

| 风险 | 等级 | 说明 |
|---|---|---|
| 日志级别变化导致输出量增加 | 低 | 新增均为 Debug/Warning，原本只在调试器可见 |
| `_logger` 为空时丢失信息 | 低 | 与现有设计一致；工厂已注入 logger |

## 6. 验证方式

1. 构建 Desktop。
2. `grep -n "Debug.WriteLine" FAP20.cs` 无结果。
3. 连接设备、加载证书、触发采集，确认 `Logs/sbi-yyyyMMdd.log` 出现证书加载与复位日志。
