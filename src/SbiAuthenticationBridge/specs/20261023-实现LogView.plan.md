## 1. 方案总览

```
业务代码/VM ──注入──> ILogger<T>
                         │ (MEL)
                         ▼
              Serilog.Extensions.Logging
                         │
                         ▼
                 Serilog Log.Logger
                    ├── SerilogLogEntrySink ──> InMemoryLogEntryStore（环形缓冲，2000 条）
                    │                                   │ EntryAdded / Cleared 事件
                    │                                   ▼
                    │                            LogViewModel（UI 线程批量消费）
                    │                                   │
                    │                                   ▼
                    └── Console Sink（调试）        LogView（过滤/自动滚动/清除）
```

- 自定义 Sink 只做「Serilog 事件 → 内存缓冲」的转换，不直接碰 UI。
- 缓冲层线程安全；ViewModel 在 UI 线程以批量方式消费，避免高频日志卡界面。
- `ILogger<T>` 由 MEL 提供，应用内部（当前为 `SbiAuthenticationBridge` 项目的 VM/Service）通过构造注入使用。

## 4. 关键实现细节

### 4.1 线程与 UI 更新
- Sink/Store 在任意线程追加，仅入队并触发事件。
- `LogViewModel` 收到事件后入 `ConcurrentQueue`，用 `Interlocked` 保证同一时刻只投递一次 `Dispatcher.UIThread.Post(Drain)`；每次 drain 按队列顺序批量写入 `Entries`。
- `Entries` 超过容量上限时移除最旧项，保证 UI 与缓冲一致。
- 过滤条件变化时从 `store.Snapshot()` 重建 `Entries`（2000 条量级，开销可接受）。

### 4.2 过滤
- 级别：`全部 / Debug / Information / Warning / Error / Fatal`，语义为「显示 ≥ 所选级别」。
- 内容：对 `Message`、`ExceptionText`、`SourceContext` 做不区分大小写的包含匹配。
- Serilog 管线最低级别设为 `Debug`，保证 UI 能看到 Debug 日志。

### 4.3 自动滚动
- `AutoScroll` 默认开启，绑定 `CheckBox`；开启时新日志追加后由 VM 触发 `ScrollToEndRequested`，View 滚动到底部。
- 关闭后保持用户当前滚动位置；重新开启立即滚到底部。

### 4.4 清除
- 清除按钮调用 `store.Clear()`：清空缓冲并触发 `Cleared`；VM 清空 `Entries`、待处理队列与计数。

### 4.5 ILogger 注入范围
- 本期只打通 `SbiAuthenticationBridge` 项目内（ViewModel/Service）的 `ILogger<T>` 注入：`Microsoft.Extensions.Logging` 与 `Abstractions` 由 `Serilog.Extensions.Logging` 传递引入。
- `Device` / `Host` / `Host.Http` 若要记录结构化日志，需要各自显式引用 `Microsoft.Extensions.Logging.Abstractions`（新增包，另立工单），本期不做，避免扩散。

## 5. 依赖链路与架构自查

- 新增代码全部位于 `SbiAuthenticationBridge`（表现层 + 组合根），不进入 Core，避免 Core 依赖 Serilog / Avalonia。
- `LogViewModel` 依赖的 `ILogEntryStore` 与自身同属表现层项目，不涉及跨层引用；`ILogViewModel` 未新增业务接口。
- 未修改 `Core` / `Device` / `Host` / `Host.Http`；`Desktop` / `Android` 仅通过共享 `App` 继承到日志初始化，无需改动。
- 无反向依赖、无跨层短路、无 ServiceLocator；全部构造注入。
- 无空 `catch`；所有 IO（Serilog 自身）不新增同步 IO。

## 6. 风险与回滚

| 风险 | 等级 | 说明 / 缓解 |
|---|---|---|
| 新增 NuGet `Serilog.Extensions.Logging` | 中 | 已在第 0 节获得确认；仅加入表现层项目，移除即可回滚 |
| 全局 `Log.Logger` 静态单例 | 低 | 当前仓库无其他 Serilog 初始化；集中在 `LoggingBootstrapper` 管理，退出 `CloseAndFlush` |
| 高频日志拖慢 UI | 中 | 批量 drain + 2000 条上限 + 仅 Debug 级别以上入缓冲；必要时可调低管线级别 |
| 自动滚动干扰用户查看历史 | 低 | 提供开关，默认开启；关闭后不再强制滚动 |
| GridSplitter 拖动挤压视图 | 低 | 设备操作区与日志面板分别设置 `MinHeight`，拖拽受最小尺寸约束 |
| `Avalonia 12.1` 退出事件 API 差异 | 低 | 落地时以 `Application.Exit` 事件为准，编译验证 |
| ViewModel 直接引用 Avalonia Dispatcher | 低 | ViewModel 属表现层，允许使用 Avalonia；不引入 Core 依赖 |
