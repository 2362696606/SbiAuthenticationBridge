# Plan:修复安卓端设备枚举无法获取到设备

> 对应 spec：`specs/20261027-安卓端无法获取到设备修复.spec.md`
> 依据：`SbiAuthenticationBridge.Android` 的配置加载链路、生成的 APK、arch.md。

## 1. 根因

### 1.1 设备服务注册本身已就位

Android 项目通过 `Application.CreateAppBuilder` 的 `PlatformServiceRegistrations` 已注册：

| 注册 | 位置 |
|---|---|
| `ISbiDeviceFactory → AndroidFap20DeviceFactory` | `AddSbiAndroidDevice()` |
| `ISbiDeviceProvider → AndroidFap20DeviceProvider` | `AddSbiAndroidDevice()` |
| `ISbiAuthenticationService` / `ISbiRegistrationService` | `AddSbiIntentServices()` |

注册链路没有问题，缺的不是服务，而是**设备配置**。

### 1.2 配置文件没有进入 APK

`Application.ConfigureConfiguration` 只从应用私有目录读取：

```csharp
var directory = FilesDir?.AbsolutePath ?? AppContext.BaseDirectory;
builder.AddYamlFile(Path.Combine(directory, AppSettingFileName), optional: true, ...);
```

而 `Config/AppSetting.yaml` 在 csproj 里是普通 `None` 项（`CopyToOutputDirectory`），
**不会被 .NET Android 打进 APK**。实测当前 APK：

```text
$ unzip -l com.CompanyName.SbiAuthenticationBridge.apk | grep -c assets/
0
```

因此设备上 `FilesDir/AppSetting.yaml` 不存在，配置为空：

1. `Device:vendorId` / `Device:productId` 读不到；
2. `AddSbiAndroidDevice` 注册的提供者回退为空设备表并记录警告；
3. 设备页显示“未发现设备”。

## 2. 方案

### 2.1 把配置作为 AndroidAsset 打包并在首启复制到 FilesDir（P0）

`SbiAuthenticationBridge.Android.csproj`：

```xml
<ItemGroup>
    <!-- 本地配置不入库，缺失时跳过，应用以空配置启动并记录警告 -->
    <AndroidAsset Include="Config\AppSetting.yaml" Condition="Exists('Config\AppSetting.yaml')" />
</ItemGroup>
```

替换原来的 `None Update` 项。

`Application.ConfigureConfiguration`：

1. 计算 `FilesDir/AppSetting.yaml`；
2. 文件不存在时，从 `Assets.Open("Config/AppSetting.yaml")` 复制到该路径；
3. 再 `AddYamlFile(path, optional: true)` 加载。

只在文件缺失时复制，保留设备上手动修改配置的可能。

### 2.2 增加设备创建日志（P1）

`AndroidFap20DeviceFactory.CreateDevice` 输出 Information：

```text
创建 Android FAP20 设备：VID=0x0483，PID=0x5725
```

配合 `AddSbiAndroidDevice` 已有的“未配置 Device 节”警告，真机日志可直接区分
“配置缺失”和“USB 未连接”。

### 2.3 不做的事

- 不重复注册设备服务（已注册，见 1.1）；
- 不引入空设备占位；
- 不改变 USB 授权时机：枚举只读 `UsbManager.DeviceList`，授权仍在点击“连接”时申请；
- 不处理证书路径（Android 上的证书部署是独立问题）。

## 3. 文件清单

| 文件 | 改动 |
|---|---|
| `SbiAuthenticationBridge.Android/SbiAuthenticationBridge.Android.csproj` | `None` → `AndroidAsset` |
| `SbiAuthenticationBridge.Android/Application.cs` | 首启从 assets 复制配置到 FilesDir |
| `SbiAuthenticationBridge.Device.Android/AndroidFap20DeviceFactory.cs` | 创建设备时输出 VID/PID 日志 |

## 4. 架构与依赖自查

- 仅 Android 平台头与设备实现包内部改动；
- 无 Core 接口变更、无新增 NuGet；
- 设备注册仍在组合根，业务代码不引用实现。

## 5. 风险

| 风险 | 等级 | 说明 |
|---|---|---|
| 本地配置未打包 | 中 | `AppSetting.yaml` 被 .gitignore 排除；换机器构建若未创建该文件，APK 内无配置，设备列表为空（日志会提示）。README/示例配置已提供模板 |
| 首启后配置不更新 | 低 | 只在文件缺失时复制；修改 APK 内配置不会覆盖设备上的旧文件 |
| 证书路径不适用于 Android | 中 | 本地配置里的证书是 Windows 绝对路径；枚举与连接不受影响，但证书下发/采集前需要在设备上部署证书并改配置 |

## 6. 验证方式

1. `dotnet build SbiAuthenticationBridge.Android`：0 error，且 APK 内出现 `assets/Config/AppSetting.yaml`；
2. 真机安装后：
   - 设备页出现一台设备（VID/PID 来自配置），状态显示未连接；
   - 点击“连接”弹出 USB 授权，允许后状态变为已连接；
   - 拔出设备后状态回到未连接，重新插入可再次连接；
   - 日志出现“创建 Android FAP20 设备：VID=…”；
3. 临时删除设备上的 `FilesDir/AppSetting.yaml` 后重启应用，文件应自动恢复。
