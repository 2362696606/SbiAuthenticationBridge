# Plan:实现 Intent 宿主

> **状态：已实施（2026-10-27）。** 前置的 FAP20 安卓迁移已完成
> （见 `specs/20261027-FAP20安卓迁移.plan.md`）；本计划只做宿主，未改动设备层。
>
> 对应 spec：`specs/20261027-实现Intent宿主.spec.md`
> 依据：arch.md、MOSIP SBI 0.9.5《Android SBI Specification》。

## 1. 协议依据（MOSIP SBI 0.9.5 Android 章节）

| 能力 | Intent action | 请求 | 响应 |
|---|---|---|---|
| 设备发现 | `io.sbi.device` | extras `input` = JSON 的 byte[] | extras `response` = JSON 的 byte[] |
| 设备信息 | `{appId}.Info` | 同上 | 同上 |
| 认证采集 | `{appId}.Capture` | 同上（带 `FLAG_GRANT_READ_URI_PERMISSION`） | extras `response` = `content://authority/path/id` 字符串 |
| 注册采集 | `{appId}.rCapture` | 同上 | 同上 |

`callbackId` 在 Android 上取 **appId**（包名）。

## 2. 现状与前置条件

- `SbiAuthenticationBridge.Host.Intent` 是空项目，未引用 Core、未进解决方案；
- Android 头目前只有 Avalonia 启动壳，没有注册任何宿主服务；
- UI 的 `SbiServiceControlViewModel` 已支持非 HTTP 宿主，无需改动；
- **前置条件**：设备提供者由 `specs/20261027-FAP20安卓迁移.plan.md` 提供，
  本计划不再改 Device / 不再新增设备实现。

## 3. 方案

### 3.1 Host.Intent 基础包（`net10.0`）

与 Host.Http 对称：只依赖 Core，实现类 internal，对外只暴露 `AddSbiIntentServices` 与分发接口。

| 文件 | 职责 |
|---|---|
| `SbiIntentHostOptions.cs` | `AppId`（包名），启动时写入 callbackId |
| `SbiIntentProtocol.cs` | action 名称、extras 键、JSON 选项（Web 命名、忽略 null） |
| `ISbiIntentDispatcher.cs` | 平台头入口：`Task<SbiIntentResult> DispatchAsync(action, input, ct)` |
| `SbiIntentResult.cs` | `InlinePayload`（byte[]）或 `ContentPayload`（JSON 字符串） |
| `SbiIntentDispatcher.cs` | action → ServiceHandle 分发、错误收敛、日志 |
| `SbiIntentHostServiceBase.cs` | `ISbiService` 公共实现：启停、启动时写入 callbackId = appId |
| `SbiAuthenticationIntentService.cs` | 认证用途（`Capture`） |
| `SbiRegistrationIntentService.cs` | 注册用途（`rCapture`） |
| `SbiIntentServiceCollectionExtensions.cs` | `AddSbiIntentServices(appId)` |

**action 路由**

| action | 处理方 | 响应形态 |
|---|---|---|
| `io.sbi.device` | 认证 + 注册 ServiceHandle 的 `DiscoverAsync`，结果合并 | JSON byte[] |
| `{appId}.Info` | 两个 ServiceHandle 的 `GetDeviceInfoAsync`，结果合并 | JSON byte[] |
| `{appId}.Capture` | `ISbiAuthenticationServiceHandle.CaptureAsync` | content URI |
| `{appId}.rCapture` | `ISbiRegistrationServiceHandle.CaptureAsync` | content URI |
| 其他 | 不处理，返回 102 错误报文 | JSON byte[] |

**错误收敛**：输入非 JSON → 102；对应用途服务未启动 → 110；无设备 → ServiceHandle 返回 202/106；
日志只记录 action、用途、耗时、结果码，不记录生物特征数据。

**生命周期**：`StartAsync` 写入 callbackId 并置运行中；`StopAsync` 置停止；重复启动抛异常（与 HTTP 一致）。

### 3.2 Android 头接入（仅宿主壳）

| 文件 | 改动 |
|---|---|
| `SbiIntentAppId.cs`（新增） | `const Value = "<ApplicationId>"` 与四个 action 常量 |
| `SbiIntentActivity.cs`（新增） | 导出 Activity，四个 action 的 `IntentFilter`（MIME `application/json`），异步处理后 `SetResult` + `Finish` |
| `SbiIntentResponseProvider.cs`（新增） | ContentProvider，`Exported = false`，读缓存文件、关闭即删 |
| `SbiIntentBridge.cs`（新增） | 静态桥：保存容器、冷启动拉起 `MainActivity` 等待就绪（≤15s）、按需启动两个宿主服务 |
| `MainActivity.cs` | 通过 App 新增的 `PlatformReady` 钩子把容器交给 `SbiIntentBridge` |
| `Application.cs` | `PlatformServiceRegistrations` 追加 `AddSbiIntentServices(appId)` |
| `.csproj` | 引用 `Host.Intent` |

**请求处理流程**：读取 `input` → 等桥就绪 → `ISbiIntentDispatcher.DispatchAsync` → 内联响应
`PutExtra("response", byte[])` 或 content URI（加读权限）→ `SetResult` + `Finish`。

**自动启动**：桥就绪后若两个宿主服务未运行则 `StartAsync`；用户在 UI 手动停止后保持停止。

**组合根钩子**：`App.axaml.cs` 新增 `public Action<IServiceProvider>? PlatformReady`。

### 3.3 不做的事

- 不修改 Device / FAP20 / 设备提供者；
- 不新增设备实现或空设备占位；
- 不实现 rCapture 预览流。

## 5. 架构与依赖自查

- Host.Intent → Core；Android 头 → SbiAuthenticationBridge / Host.Intent，通过 `AddXXX()` 注册；
- 实现类 internal，只暴露注册扩展与分发接口；
- 无 Core 接口变更；无新增 NuGet。

## 6. 风险

| 风险 | 等级 | 说明 |
|---|---|---|
| 冷启动时序 | 高 | Intent 可能先于 Avalonia 初始化；拉起 MainActivity + 15s 等待，需真机验证 |
| Activity 生命周期 | 中 | 处理完即 `Finish`，依赖 MainActivity 保持进程存活 |
| 无法本机验证 | 高 | 无 Android 设备，只能构建验证 |
| IntentFilter MIME 匹配 | 中 | 按规范声明 `application/json`；客户端未带 type 时需补一条无 MIME 的 filter |

## 7. 验证方式

1. `dotnet build SbiAuthenticationBridge.Android`：0 error；
2. 真机：`io.sbi.device` 返回设备列表；`{appId}.Info` 返回设备信息；
   `{appId}.Capture` 的 content URI 可读且读后失效。
