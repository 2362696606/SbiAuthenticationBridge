# Plan:FAP20 原始输入输出日志

> 需求：为 FAP20 添加日志，打印设备原始输入与输出。
> 依据：arch.md、现有 `FAP20`（已注入 `ILogger<FAP20>`）、`FtmProtocolCodec`。

## 1. 现状

- `FAP20` 已通过构造注入 `ILogger<FAP20>`，但仅用于 `LogInit`，没有打印命令收发。
- 命令入口统一为 `FtmNativeMethods.*`，请求是紧凑二进制 payload，响应是
  JSON 文本或固定长度二进制帧。
- 文件日志 Sink 已接入（Debug 级别），原始收发可以直接落盘。

## 2. 方案

### 2.1 新增 FAP20 内部日志辅助方法

在 `SbiAuthenticationBridge.Device/FAP20.cs` 增加：

```csharp
private void LogRequest(string operation, ReadOnlySpan<byte> payload);
private void LogTextResponse(string operation, int resultCode, string response);
private void LogBinaryResponse(string operation, int resultCode, ReadOnlySpan<byte> response);
```

- 仅在 `LogLevel.Debug` 启用时格式化，避免无谓开销；
- 请求：长度 + 大写十六进制；
- 文本响应：长度 + 原始 UTF-8 文本（JSON 不截断）；
- 二进制响应：长度 + 十六进制（最多 512 字节，覆盖证书回执与 DKL 公钥帧）；
- 统一附带原生命令名与返回码，失败响应也能看到。

### 2.2 覆盖的命令

在原生调用后、`ThrowIfFailed` 之前记录响应，保证失败时也能拿到原始返回：

| 命令 | 请求 | 响应 |
|---|---|---|
| `LoadCertificate` | hex | 二进制（失败时按文本打印） |
| `Discover` | hex | 文本 |
| `GetDeviceInfo` | hex | 文本 |
| `SetTime` | hex | 返回码 |
| `CaptureAuth` | hex | 文本 |
| `CaptureReg` | hex | 文本 |
| `GetDklPublicKey` | hex | 二进制 |
| `SetDklCertificate` | hex | 返回码 |
| `Send` | hex | 无 |
| `Recv` | 无 | 二进制 |
| `SetDevStatus` / `DeviceReset` | 参数 | 返回码 |

### 2.3 日志格式

```text
[DBG] ftm_capture_auth 请求 96B HEX=01...
[DBG] ftm_capture_auth 响应 rc=0x0 TEXT={"biometrics":[...]}
```

不新增日志文件配置，沿用现有文件日志与内存日志。

### 2.4 不修改

- 不改变命令编码、超时、重试、错误映射；
- 不新增 NuGet；
- 不在 Info 级别重复打印，避免日志膨胀。

## 3. 文件清单

| 文件 | 改动 |
|---|---|
| `SbiAuthenticationBridge.Device/FAP20.cs` | 新增原始收发日志辅助方法，并在各原生命令调用处接入 |

## 4. 架构与依赖自查

- 日志位于 Device 基础设施层，依赖 `Microsoft.Extensions.Logging`，符合 arch.md；
- 不引入 Host/UI/HTTP 依赖；
- 不吞异常，`ThrowIfFailed` 语义不变。

## 5. 风险

| 风险 | 等级 | 说明 |
|---|---|---|
| 响应包含生物特征 JWT、sessionKey | 中 | 仅写入本机 Debug 文件日志与 LogView；CTK 排查结束后删除 |
| 单条采集响应约 26KB，日志量增大 | 中 | 文件日志已按天 + 32MB + 保留 7 个滚动 |
| 二进制响应只打印前 512 字节 | 低 | 覆盖现有证书回执与 DKL 公钥帧；`Recv` 按实际返回长度打印 |
| Debug 日志影响性能 | 低 | 仅在 `IsEnabled(Debug)` 时格式化 |

## 6. 验证方式

1. 构建 Desktop。
2. 启动应用，连接设备，执行一次 `/device`、`/info`、`/capture`。
3. 检查 `Logs/sbi-yyyyMMdd.log`：
   - 每个命令都有请求 HEX 与响应原文；
   - 采集成功时能看到 `data`、`dataDecoded`、`sessionKey`、`thumbprint`；
   - CTK 失败时能看到固件原始错误响应。
4. 关闭应用，确认日志完整。

## 7. 不在本次范围

- USB 底层 EF01 帧头/CRC 的抓包；
- 日志脱敏；
- 文件日志滚动策略调整。
