# Plan:FAP20 安卓迁移

> 来源：2026-10-27 用户指令——先完成 FAP20 安卓迁移，Intent 宿主实现延后。
> 依据：arch.md、`E:\code\local\ftmBridgeAPI\android`、现有 Desktop 设备实现。

## 1. 目标与范围

**目标**：Android 端通过 `UsbManager` 打开 FAP20，复用现有 `FAP20` / `FAP20Proxy` 的
发现、信息、状态、证书与采集逻辑；应用 UI 能识别并操作设备。

**本轮不做**：

- Intent 宿主（`specs/20261027-实现Intent宿主.plan.md` 保留，后续实施）；
- 任何 SBI 服务宿主（HTTP / Intent）；
- rCapture 预览流；
- x86_64 / 其它 ABI。

## 2. SDK 结论：C/C++ 无需改动

| 事项 | 结论 |
|---|---|
| Android NDK 工程 | `ftmBridgeAPI/android/` 已完整（libusb 1.0.26 静态链接、usbfs 后端） |
| 产物 | `android/build/libs/arm64-v8a/libftmBridgeAPI.so` 已生成（540KB） |
| 导出符号 | `llvm-nm` 确认含 `ftm_open_fd`、`ftm_log_init_path`、`ftm_set_config_path` |
| 打开方式 | Android 不能枚举 USB，必须由 `UsbManager` 打开后把 `UsbDeviceConnection` 的 fd 传给 `ftm_open_fd` |
| 设备参数 | 仓库内置 `FingerPrintDebug.INI`：VID `0x0483`、PID `0x5725`、BULKOUT `0x01`、BULKIN `0x82`（SDK 默认一致） |

## 3. 方案

### 3.1 Device 层：抽象“打开设备 + 在线监测”

现在 `FAP20` 直接依赖 `UsbPresenceMonitor`（setupapi.dll，仅 Windows）和 `ftm_open()`。
把它抽成接口，桌面实现保持原行为，Android 提供自己的实现。

| 文件 | 改动 |
|---|---|
| `IFtmDeviceOpener.cs`（新增，public） | `bool IsPresent`、`event PresenceChanged`、`string? LogFilePath`、`Start()`、`bool Refresh()`、`Task<IntPtr> OpenAsync()`、`IAsyncDisposable` |
| `WindowsFtmDeviceOpener.cs`（新增，internal） | 包装现有 `UsbPresenceMonitor` + `FtmNativeMethods.Open()`，逻辑与当前 `FAP20.ConnectAsync` 完全一致 |
| `Interop/ICT/FAP20/FtmNativeMethods.cs` | 新增 `ftm_open_fd(int)`、`ftm_log_init_path(string,int)`（UTF-8 字符串） |
| `FtmDeviceNative.cs`（新增，public） | 供平台设备包调用的原生入口：`OpenFd(int)`、`SetLogPath(string,int)` |
| `FAP20.cs` | `_presenceMonitor` → `_deviceOpener`；新增构造 `FAP20(IFtmDeviceOpener, ILogger<FAP20>?)`；原 `(vid,pid,logger)` 构造内部改为创建 `WindowsFtmDeviceOpener`；`ConnectAsync` 用 `Refresh()` / `await OpenAsync()`；日志初始化按 `LogFilePath` 选择 `ftm_log_init_path` 或 `ftm_log_init`；释放时释放 opener |

桌面调用点（`FAP20Factory`）不变。

### 3.2 新增 `SbiAuthenticationBridge.Device.Android`（`net10.0-android`）

| 文件 | 职责 |
|---|---|
| `AndroidFtmDeviceOpener.cs` | `UsbManager` 按 VID/PID 查找 → 权限（`RequestPermission` + 广播 + 15s 超时）→ `OpenDevice` → `ClaimInterface(0)` → `ftm_open_fd(FileDescriptor)`；`DeviceDetached` 广播转 `PresenceChanged(false)`；释放时先由 `FAP20` 调 `ftm_close`，再 `ReleaseInterface` / `Close` |
| `AndroidFap20DeviceFactory.cs` | 读 `IConfiguration` 的 `Device:vendorId/productId`，创建 opener + `FAP20` + `FAP20Proxy` |
| `AndroidFap20DeviceProvider.cs` | `ISbiDeviceProvider`，与桌面同一模式：启动时创建一个设备实例 |
| `SbiAndroidDeviceServiceCollectionExtensions.cs` | `AddSbiAndroidDevice()`：注册设备工厂与提供者 |
| `native/arm64-v8a/libftmBridgeAPI.so` | 从 SDK `android/sdk/libs/` 复制进仓库，避免外部绝对路径 |
| `SbiAuthenticationBridge.Device.Android.csproj` | `AndroidNativeLibrary` 打包 .so；引用 Device/Core 与已有的 DI/Logging/Configuration 包 |

行为约定：

- **未配置 VID/PID**：不创建任何设备实例，`Devices` 为空（不伪造设备），日志给出警告；
- **权限被拒 / 打开失败**：不缓存失效句柄，下次连接重新申请；
- **拔出**：广播触发 `PresenceChanged(false)`，`FAP20` 关闭句柄，下次连接重新走 UsbManager；
- SDK 日志：`ftm_log_init_path(FilesDir/sdk_runtime.log, Warn)`；
- BULKOUT/BULKIN 保持 SDK 默认 `0x01/0x82`，暂不调用 `ftm_set_config_path`。

### 3.3 Android 头接入

| 文件 | 改动 |
|---|---|
| `Application.cs` | `PlatformServiceRegistrations = services => services.AddSbiAndroidDevice()` |
| `Properties/AndroidManifest.xml` | `<uses-feature android:name="android.hardware.usb.host" android:required="true" />` |
| `SbiAuthenticationBridge.Android.csproj` | 引用 `SbiAuthenticationBridge.Device.Android` |
| `Config/AppSetting.example.yaml` | 增加 `Device` 配置节示例 |
| `Config/AppSetting.yaml`（本地、不入库） | 增加实际 VID/PID |

配置示例：

```yaml
Device:
  vendorId: "0x0483"
  productId: "0x5725"
```

UI 侧无需改动：`DevicesViewModel` / `DeviceOperateViewModel` 已经只依赖 Core 的
`ISbiDeviceProvider` / `ISbiDevice`；`ServiceOperateViewModel` 在无宿主服务时显示不可用。

## 5. 架构与依赖自查

- `Device.Android → Device / Core`：同层实现包，只通过 `AddSbiAndroidDevice()` 对外；
- Android 头只调用注册扩展，不直接 new 设备实现；
- 无 Core 接口变更；无新增 NuGet（复用已批准的 DI/Logging/Configuration 包）；
- `FAP20` 的改动属于“本次变更直接触及的逻辑”，桌面构造签名保持不变。

## 6. 风险

| 风险 | 等级 | 说明 |
|---|---|---|
| 桌面回归 | 高 | `FAP20` 打开流程改为 opener 抽象，需回归一次连接、采集、拔出重连 |
| USB 权限交互 | 中 | 首次需用户授权；PendingIntent/广播行为需真机确认 |
| `FileDescriptor` 绑定 | 中 | 依赖 .NET Android 的 `UsbDeviceConnection.FileDescriptor`；缺失时需 JNI 兜底 |
| ABI 限制 | 中 | 仅 arm64-v8a，模拟器不可用，必须真机 + USB OTG |
| 无法本机验证 | 高 | 当前环境无 Android 设备，只能构建验证；最终需真机验证发现、信息、采集 |
| 原生库入库 | 低 | 540KB 二进制进仓库；来源与重建方式写入 README/注释 |

## 7. 验证方式

1. 构建：
   - `dotnet build SbiAuthenticationBridge.Desktop`：0 error；
   - `dotnet build SbiAuthenticationBridge.Android`：0 error；
2. 桌面回归：连接 FAP20 → DISCOVER / INFO / CAPTURE 正常；拔出后 `IsConnected` 变 false，重新插入可重连；
3. 真机：
   - 首次连接弹出 USB 授权，授权后 `Devices` 中出现设备；
   - 设备状态、证书下发、采集命令返回与桌面一致；
   - 采集中拔出设备，界面显示未连接且不崩溃。
